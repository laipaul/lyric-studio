# Screens

_Part of the project brief (CLAUDE.md links here). Every screen of the studio: Library, Song page tabs, Storyboard, Textboard, Collections, Content board, Studio. Moved word for word from CLAUDE.md on 30 Oct 2026; keep it up to date when this area changes._

Screens (Step 6, in the Life Lyrics look: dark, Cinzel headings, accent pink):
- **Library** (start page): song cards (cover, title on up to 2 lines, artist/EP, per-platform chips and status) with search; Step H (src/library-status.ts, pure): one colour per chip — grey not made (or all discarded), amber made but not approved ("to review"), green at least one approved video in any run (the count = approved), red failed / stopped (reasons and Resume in its popover), pulsing while rendering; "Standard" only when the song has some; full labels that never truncate (wrapping chips); a summary line ("2/5 ready · 1 to review · 1 error", "No videos yet"); one action per card: Generate (?tab=generate, no videos), Fix (?tab=videos, a failed run), Resume (a stopped run, /api/runs/resume), Review (?tab=videos, videos to review), none when everything made is approved; "Same cover as …" when another song has the very same cover picture (by content); filters All · No videos · Needs review · Errors · Ready (with counts; Ready = something approved and nothing to review, failed or rendering) and Sort: Last made (default; added counts when never made) · Title · Date added; "+ New song" (WAV/MP3 + lyrics.txt required, or "Instrumental" with an optional story.txt; cover, hints .lrc, title, artist with a dropdown of used artists, EP optional) creates or updates the project (found by the song's content). While songs or collections still use the old folders, a banner offers "Preview" (dry run) and "Migrate" (6.2c-1).
- **Song page** tabs (6.2c): **Assets** (6.2c-1: song, lyrics.txt, cover, hints.lrc with Replace (old file kept in .studio\replaced\); the song's own clips by drag-and-drop with thumbnail, orientation, duration, resolution, duplicate warnings and usable counts for 9:16 / 16:9; Remove moves to clips\_removed\, never deletes), **Lyrics** (5c.2: every line with its stamp, where it starts now (vocal-start check / set by hand), what the viewer sees (fades in / readable / leaves, by the render's own lyricFrames), confidence; flagged and low-confidence lines highlighted with the reason; nudges −0.5 / −0.1 / +0.1 / +0.5 s, ▶ plays 3 s from 1 s before the line (the song file is served for this), Undo, Reset line, Save -> hand-set lines in hints.lrc; lyrics.txt editor: label / title-at-the-top / credit / repeat-mark lines flagged with "Remove", saving keeps the old file in .studio\replaced\ and warns first when words change (re-align on the next make; hook markers and blank lines do not), earlier versions Restore; "Checked by ear" on a low-confidence or flagged line: stored with the song in .studio\lyrics\checked-by-ear.json (alignment hash, words, start), it turns that line's timing WARNs in QA (confidence, starts before the vocals, flagged for review) into the note "line 40 "…": checked by ear" until the alignment, the words or the line's start change (then "checked before, but its time changed since: check it again"); pnpm make logs it and the manifest has lyric_timings[].checked_by_ear), **Generate**, **Videos**; **Style** (6.2c-2a: every recipe field with its value and source (library / artist's brand / this song, per platform where it can differ), Reset and Lock, saved to song.json at once; fonts: bundled + WORKSPACE_DIR\fonts only, with a live preview line incl. é è ç à ô and a warning when a font lacks them); Generate (6.2c-2a) opens with the resolved recipe ("From the recipe (glide · YouTube: cinematic-fade)", the recipe's platforms, videos and target length per platform, section, layout), sends only what is changed, locked fields disabled, "Save to song"; 6.2c-2b adds **Post** (approved videos only, per platform: play, caption + hashtags per artist and platform, YouTube title / description / tags, downloads, Open folder; nothing is posted automatically) and finishes Videos: each run's settings from its manifests (effects, fonts, accent, collections, section, layout; manifests record collections and target_length) next to the recipe now, differences marked, "Use these settings" -> Generate (?tab=generate&from=<run>) with that run's platforms, videos, effects, collections, layout and section: an auto section as the exact times it used ("0:34–1:06 (from that run)") with one click back to "auto · <its target length>", a fixed one exactly; locked fields stay the recipe's. Tasks "Clear finished": done, failed and cancelled-before-start entries at once; stopped / interrupted ones that can still Resume only after "N stopped task(s) can still resume — clear it too?"; never running or queued; never a file; finished entries older than 24 h are hidden anyway. `pnpm brand:set <platform> <setting> <value>` edits brand.json perPlatform and tidies identical unlocked song overrides. In the app, a failed request says "Lyric Studio's server isn't responding — restart it with Start Lyric Studio.cmd"; the launcher restarts a stopped process on its own (no kill-all), timestamps its log and keeps the previous one. Videos (6.2a): every run of the song (also command-line runs), newest first, grouped by platform; tiles with a still frame that plays muted on hover, QA badge with reasons (hover/click), favourite / approved / discarded (hidden, never deleted), compare 2-3 videos side by side (one play/pause and timeline, differences highlighted), "ready to post" (caption + hashtags from the artist's template, downloads, open folder). Generate panel (6.2b): platforms, collection (remembered), verse/hook effects (brand defaults), title/artist/EP/cover, advanced (videos per platform, section, YouTube layout, allow fill, re-align) -> a queued make_run that the worker makes one at a time with makeVideos (same code as pnpm make). Header Tasks menu: live progress of studio runs and of terminal runs that are rendering; Stop after the current video (the rest becomes interrupted); one-click Resume of an interrupted run into its own folder (studio runs with their stored options, terminal runs from the command in their manifests; moved files replaced by the project's copies).
- **Storyboard** tab (stage 1 view + stage 2 editing in "The plan now": the story strip (every clip of the run in story order; drag onto another clip or arrows -> the song folder's clips.json "order", file names the fallback), the clip editor (click a clip or a shot: in / out with "set here", speed 0.5-1x, best moment; clips.json "clips"), drag a clip onto a lyric line -> a song.json anchor (replaces that line's; "remove the anchor" on the shot); every change re-plans and Generate renders exactly that plan; a "Follow playback" checkbox next to Zoom (off by default, remembered in the browser) scrolls the timeline with the playhead, a third from the left, until the user scrolls by hand; the header WARNs "Loop flows" with the failing points and suggests target lengths whose end loops well (loopSuggestions: the first bar after a complete line, 0.5-1.5x the target, beat + level + harmony pass)): a video's cut plan without rendering (makeVideos dryRun: the same planner Generate renders with; no run folder, rows, song.json or .lrc; never aligns) or a past run's (its manifests); rows: bars, waveform (song decoded once), hook sections, lyric lines at their on-screen times (⚓ anchored), shots as thumbnail blocks (length, cut, in/out, speed, ⚓ line, ★ best moment = the strongest 2 s by motion/colour/contrast, cached in workspace\cache\best-moments.json; a best moment set in the clip editor (stage 2) always wins; ◐ dissolve, ↻ Reels loop ending) with warnings (choppy slow motion < 0.75x, clip too short, anchor conflicts, the same clip within 3 shots); anchors outside the section listed; click the timeline to play the low-res preview from there. Planned in a child process (packages/video/scripts/storyboard.ts) so the studio never bundles the render code.
- **Textboard** (the song's text layer, textboard.json in the song folder; src/textboard.ts pure, src/node/textboard.ts files): ordered cards title, byline, tagline, then every lyric line (Lyrics tab numbers), each with only its overrides (position lyrics | with-title | top | upper | centre | lower inside the lyric/safe area, size 0.5-2, hold s, effect, font/weight/italic; title cards also text, show) and "roles" rules (title, byline, tagline, verse, hook); timing always from the alignment / hand times / display rules, never re-aligned; no textboard.json = the brand's defaults, unchanged videos (YouTube title + artist as text cards drawn exactly like the old title overlay; vertical: no title unless show). Cards follow lyrics changes by words; lost ones listed, never silent. Storyboard Textboard row: click a card -> editor (place, size, hold, effect, text/show) with live preview (previewCard), Save re-plans, Reset per card. Templates (workspace\templates\<artist>\<name>.json): the design without the words (roles + title cards' looks; per-line changes excluded, counted); Apply fills in the song's own title, byline, tagline, lyrics. Picture swap: Storyboard "Pictures" (clipSet, this plan only) and Generate "Picture versions" / --pictures "song+wedding,city" (one video per clip set, same textboard; not with pairings or --resume); an anchor whose clip is missing becomes a slot (amber line, "needs a clip", QA WARN "slot: line N … needs a clip") until refilled. Manifest textboard {file, hash, template, changes, cards} and picture; Videos tab rows Textboard / Picture versions. Title opening (Step D; recipe titleOpening off (default) | on, per platform; Reels, TikTok, Shorts): the auto section starts up to 2 bars before the first hook (1 bar when 2 bars > 5 s; section.ts titleLead); title + byline shown on the frame's upper third line, tagline (song.json "tagline", Assets tab, empty = none, never the EP) on the lower third line (positions upper-third / lower-third, 12% inside the safe area), all ending when the first lyric line fades in (never overlapping it); a title font lacking characters gets Noto Sans JP / Serif JP (TextCardProps.fallbackFont); the card editor's font picker and "Use as the brand's title font" (asks first; POST /api/brand/title-font -> brand.json titleFont). Every Reels / TikTok / Shorts video gets cover.jpg (vN.cover.jpg when several; renderStill of coverProps: title cards, no lyrics, no audio, on the hook's frame; Ready to post download). QA (vertical videos with title cards): "Title cards inside the safe zone", "… inside the profile grid (3:4)" (the centred 3:4 crop), "… clear of the first lyric", "Title characters"; assess.ts turns them into plain points (shorter tagline / smaller size / another font).
- **Collections** (header link next to Library; /collections, node/collections.ts, API /api/collections[/<name>]): one card per shared collection (collections\<name>\, older clips\<name>\) with 4 thumbnails, clip / photo count, video length, what 9:16 and 16:9 can use (the render's rule) and the songs that use it (song.json "collections", else remembered); "New collection" (a dialog; an empty folder, Windows-safe name); each card's ⋯ menu: Rename (folder renamed via relocatePaths, song.json "collections" (also locked), remembered collections and queued/resumable runs follow; not while a song using it renders), Open folder, Delete (asks, naming the songs; folder -> collections\_removed\<name> (removed <date>), never deleted; songs stop naming it; "Removed collections" with Restore, " (2)" when taken); empty card "Add clips"; chips "9:16 · N" / "16:9 · N" (amber below the clip count); "Used by N songs" (names on hover); "Same clips as X" (identical content; the copy songs use least is flagged). sharedCollections never lists _removed. A collection's page: the Assets-style grid (orientation, length, size, duplicates by content "used once"; hover plays the clip, served by /api/files), drop or "Add clips" (copied, content already there not copied), Remove -> _removed\ (never deleted) with Restore, Open folder (Explorer), links to the songs. Shared helpers in assets.ts: folderClips, importClipsInto, removeClipFrom, restoreClipTo.
- Every visible menu item must lead somewhere real (the Studio editor is not in the menu until it has content).
- **Content board**: Generated -> Approved -> Scheduled -> Published, with manually entered results (Step 6.3).
- **Studio**: left panel (project, sections, lyrics, text styles, cinematic bars), centre phone-shaped live preview with "Render video", right panel (media collections, add clips, filter all / in use / unused), bottom bar (play, undo, shuffle, Beat Synced with cut rate 0.5x / 1x / 2x / Off, timeline with clip thumbnails and beat ruler), variations strip under the preview.
A header "Tasks" menu shows render progress.
