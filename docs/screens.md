# Screens

_Part of the project brief (CLAUDE.md links here). Every screen of the studio: Library, Song page tabs, Storyboard, Textboard, Collections, Content board, Studio. Moved word for word from CLAUDE.md on 30 Oct 2026; keep it up to date when this area changes._

Screens (Step 6, in the Life Lyrics look: dark, Cinzel headings, accent pink):
- **Feature icons** (1 Nov 2026; apps/studio/src/lib/feature-icons.tsx FEATURE, FeatureIcon, PlatformMark; data-feature-icon, data-platform-mark): one icon and colour per feature, the same on every screen: Song music note white, Theme palette pink (brand), Clips film teal, Collection a stack teal, Lyrics and card text "T" amber, steps Prepare ✓ / Shape ◇ / Make clapperboard / Review eye / Post paper plane, Automatic wand. Platform marks are plain shapes in each platform's colour (not the platforms' logos), shown before the platform's name on Library cards.
- **Library** (start page): **New song** as the first tile of the grid (data-new-song-tile, 1 Nov 2026, like Themes, Collections and Releases; no button at the top), then song cards (cover, title on up to 2 lines, artist/EP, per-platform chips and status) with search; Step H (src/library-status.ts, pure): one colour per chip — grey not made (or all discarded), amber made but not approved ("to review"), green an approved video in the latest run, or in an older run when the latest kept none (the count = approved in any run; a new unreviewed render turns the chip amber again), red failed / stopped (reasons and Resume in its popover), pulsing while rendering; "Standard" only when the song has some; full labels that never truncate (wrapping chips); a summary line ("2/5 ready · 1 to review · 1 error", "No videos yet"); one action per card: Generate (?tab=generate, no videos), Fix (?tab=videos, a failed run), Resume (a stopped run, /api/runs/resume), Review (?tab=videos, videos to review), none when everything made is approved; "Same cover as …" when another song has the very same cover picture (by content); the song's theme under the artist line (data-card-theme; listSongs first puts every song on a theme); "Deleted songs (N)" under the cards (data-deleted-songs; folded) with Restore per song (data-song-restore); filters All · No videos · Needs review · Errors · Ready (with counts; Ready = something approved and nothing to review, failed or rendering) and Sort: Last made (default; added counts when never made) · Title · Date added; "+ New song" (WAV/MP3 + lyrics.txt required, or "Instrumental" with an optional story.txt; cover, hints .lrc, title, artist with a dropdown of used artists, EP optional) creates or updates the project (found by the song's content). While songs or collections still use the old folders, a banner offers "Preview" (dry run) and "Migrate" (6.2c-1).

"Use these settings" (a past run) still sends that run's part, length, layout and videos and shows "Also keep that run's settings for this song". **Review** = Videos · Post. The header's title and pencil open Details (data-song-title-edit); Delete song stays in its ⋯. Old links: ?panel=clips|shot → shots, auto → part, song → ?tab=details, make → Make, theme (+ ?edit=) → the theme editor; ?part=videos|looks|options opens a Make tab. Shape's theme panel: the editor, or "This song uses: X" with Edit theme and a link to the Themes page (the only theme library: new, rename, duplicate, delete, restore).

The chips ARE the song's settings: song.json platforms (the ones on) and variations (their counts), saved at once (a song with none chosen yet shows every platform you post to, once each; turning the last one off is not saved). Counts follow the one rule (recipe.ts videoCount / studioCounts): the song's own count, else 1 in the studio; the presets' numbers are only for pnpm make without a count. Buttons: data-one-of-each "One of each (N)" (one video for every platform on; replaces the release pack) and data-make-videos "Make N videos" (the counts). The song line (title, clips, look), Advanced folded (data-advanced: allow clips of the other orientation; a pointer to Time the lyrics again). Both buttons are disabled with the reason (data-make-blocked: a blocking to-do "First: …", no lyrics, no platform on). "Use these settings" (?from=<run>): the chips start from that run, not saved, under a banner (data-from-run "From the run of …", the run's part of the song with Switch to auto, "Also keep that run's settings for this song"). **Compare looks** (data-make-part=looks): its own platform chips (data-compare-chips, Reels by default, no Canvas), Other themes (1-3, never the song's own: data-compare-themes, picker compare-themes) or Other pictures (2-4 clip sets: data-picture-versions); one video per platform per look, each a try with its own shot plan; the song's own v1 is the baseline, made too where a platform has none (data-compare-baseline says which). Review labels a try on its card (data-video-try "try: theme Night Drive"). The old release pack, the Videos/Options tabs, Generate's run chips, its "Theme for this run" and Shape-side "What to make" rows are gone (platforms and counts live in one place only).

- **Version names** (11 Nov 2026, bug fix; src/node/versions.ts): the name shown everywhere (Review's cards, Shape's video picker for past runs, Post and its file names, the player, Compare, the Library's details) is a song-wide version number per platform: v1, v2, v3... in the order the videos were made, never reused (a discarded or deleted video keeps its number). Before, the name was the file's number inside its run folder, so every Make run called its video "v1". The files on disk keep their names (exports\<run>\reels\v1.mp4); VideoInfo.name is the version, VideoInfo.file / .index the file and its variation. Kept in `.studio\versions.json` (docs/data-model.md); existing videos get their numbers the first time they are read, in creation order. Tries are not versions (they keep "Try · <theme>" and "based on vN"). The "Plan now" list in Shape (v1..vN of what Make would plan) is the plan's own video slots, not made videos. `pnpm versions "<song>"` lists the file -> name mapping.

- **Post downloads** (11 Nov 2026, decided with the user; lib/save-file.ts, ready-to-post.tsx): every file button of the Post panel (Video, Captions (.srt), Thumbnail, Cover, publish.txt; data-save-file, data-save-name) opens a "Save as" picker (File System Access API, Chrome / Edge) in the last folder used for this song and platform (else this song's folder, else the last parent folder, else Downloads); other browsers: a normal download. "Save all to…" (data-save-all) writes every file of the post into one folder picked; "in a folder named “<song>”" (data-save-subfolder, on by default, remembered in this browser) makes the picked folder the parent: the files go into a subfolder named after the song and the next song's picker opens in that parent (a web page cannot open a folder's parent itself). Names: "<song> - <platform>[ vN].mp4", ".srt", " - thumbnail.jpg", " - cover.jpg", " - publish.txt" (Windows-safe). The folders are remembered in this browser's IndexedDB (lyric-studio-save: the browser's folder handles, never paths). These are the app's only download buttons (Make has none; the release pack is gone).
- **Look simplified** (11 Nov 2026, decided with the user; rule: "the theme decides how everything looks, the song decides what appears"): Shape → Settings → Look holds three things. **Theme** (data-look-theme): the Look bar (the song's theme, Change) and "Edit theme <name>" (data-look-edit-theme). **On-screen text** (data-on-screen-text): one row each for Title, Artist and Credits (data-on-screen=title|byline|tagline, data-on="1|0"), with its words and a switch (data-on-screen-toggle, role=switch; disabled while the text is empty).
