# Brand, fonts and publishing texts

_Part of the project brief (CLAUDE.md links here). brand.json and logo, fonts, font pairings, artist per project, captions for posting. Moved word for word from CLAUDE.md on 30 Oct 2026; keep it up to date when this area changes._

- Themes (31 Oct 2026): a song's verse / hook fonts, weights, italics, effects, Breathe, add-ons and accent colour come from its **theme** (workspace\themes\<name>\theme.json; see docs/data-model.md "Themes"), which sits above brand.json in the recipe. brand.json "theme" names the artist's default theme (made from brand.json on first use). A font pairing chosen in the Theme panel goes into the theme, not brand.json; "Save to brand" is not offered there.
- Brand: WORKSPACE_DIR\brand\brand.json (title font Cinzel, verse font Cormorant Garamond, hook font Kaushan Script, accent colour, logo corners and size) + logo.png. Logo: only on the platforms in brand.json logo.platforms (default ["youtube"]: no logo on reels, tiktok, shorts, canvas or other vertical presets); YouTube bottom-right by default (logo.youtube), fading out (0.5 s) before the last-20-s end-screen window; 9:16 when enabled: logo.vertical ("auto" = bottom right). Always anchored to a frame corner with a fixed margin (3% of the width), never mid-frame (QA "Logo in a frame corner"), never over the lyrics (QA). Lyrics use the brand fonts; --font/--font-hook override. Thumbnails and title cards use the brand title font.
- Fonts: bundled @fontsource families (fonts/LICENSES.md; incl. Cormorant Garamond, Playfair Display, Great Vibes, EB Garamond, Spline Sans, Space Mono, Bitter, Grand Hotel, Lato, Abril Fatface, Poppins, Arima, Mulish, Special Elite, Noto Sans JP / Serif JP: CJK families load only the pieces the lyrics use) plus any .ttf/.otf/.woff/.woff2 in WORKSPACE_DIR\fonts (D:\videomaker\workspace\fonts; shown in the Style tab); props list the exact font files, so preview and render load the same ones. Weight and italic per font (recipe verseWeight / hookWeight 100-900, verseItalic / hookItalic; brand.json verseFont/hookFont/titleFont weight + italic; per platform; Reset and Lock): the exact file, else the nearest weight (upright when no italic) with a warning naming it; text is drawn with font-synthesis: none (never a fake bold or italic). The recipe's weight applies to every variation (Simple and Bold differ in case, shadow, animation and size). The manifest records settings.fonts (family, weight, italic, pairing).
- Font pairings (presets/font-pairings.json: verse + hook (+ optional title) font with weight and italic, a note, an optional warning; "Current brand" = the artist's brand.json fonts, first): Shape → Style → Look shows them as ONE dropdown "Font pairing" (components/pairings-row.tsx; a Radix popover with a listbox, not a native select, so that hovering can preview; no card thumbnails and no grid: the big Look preview already shows the pair). Each option: the name ("brand" chip, "try this" for the recommended pair, a muted "!" when it has points), its fonts in one small line (verse · hook, e.g. "Cormorant Garamond · Playfair Display italic"; same family: "Cormorant Garamond 400 / 600 italic"; exact faces as tooltip) and a one-line sample of the song's own words drawn in the pair's own fonts (verse font, then hook font) at 18 px. **Hovering or keyboard-highlighting an option shows that pair in the big preview** (nothing saved; Escape or closing without a choice puts the song's fonts back); **choosing one applies it to this song** (song.json; locked fields kept, named) and the dropdown then shows it (✓ and brand-coloured border on the option; pink is reserved for it). Next to the dropdown: "Back to the brand" (resets the song's fonts) and a small "Save to brand…" link for the chosen pair (asks first; writes brand.json, with the title font). Notes per pair (src/node/pairings.ts pairingNotes: each in plain words + the technical detail): missing é è ç à ô, characters of the song's lyrics a font lacks (e.g. Japanese) — both need a creative choice (another pair); low contrast over the frame (3:1, thin strokes 4.5:1); a thin script on hook lines over 24 characters; the pair's own warning. They are not shown in the list (a non-chosen option only has a tiny muted "!" with the technical text as tooltip): under the dropdown, the **chosen** pair's notes in plain words (e.g. "Lyrics may be hard to read over bright clips like this one: the app adds a soft backing behind them when your clips need it"), the ratios under "Details". Readability is the app's job: with Lyric readability "auto" (the default) the render adds the soft backing by itself (see docs/assessment.md); the line says so, or that the backing is on ("strong"), or that "normal" switched it off. Compare: Generate's "Compare font pairings" (2-3) or pnpm make --pairings a,b: one video per pairing with the same section, clips, order and style.
- Artist per project (default "Life Lyrics"; --artist or the New song form): titles, thumbnails, overlays and publish texts use it; its brand is workspace\brand\<artist>\brand.json when present, else workspace\brand\ (Life Lyrics). The EP is stored with the project too (--ep or the form) and reused.
- Captions for posting per artist and platform: brand\<artist>\publish-<platform>.txt (e.g. Pômé in French) else brand\publish-<platform>.txt (English defaults created the first time; placeholders {{song}} {{artist}} {{ep}} {{epLine}} {{hook}} {{songTag}} {{artistTag}} {{year}}); YouTube uses the publish.txt next to the video (its template: brand\<artist>\publish-template.txt else brand\publish-template.txt). Canvas has no caption. Song links (1 Nov 2026; src/song-links.ts pure, src/node/song-links.ts files, API /api/songs/<id>/links): song.json "links" [{service, url, label?}] (Assets tab → Links: paste a link, detectService names it, a SearchPicker changes it; services in LINK_SERVICES grouped Stores / Smart links & marketing / Artist & social, "other" with its own label; a wrong entry is left out, never blocking the song) and "postLinks" {<platform>: [urls]} (Post panel → Links for this post: the pick per platform, each link with Copy; without a pick pickedLinks gives YouTube all links, the other platforms the one bestLink: a smart link, else website, else Spotify, else the first). Placeholders in caption templates and publish-template.txt: {{bestLink}} {{smartlink}} {{links}} (stores, smart links and website, "Spotify: url" per line) {{listen}} ("Listen:" + them) {{socials}} {{follow}} ("Follow:" + the social pages) and one per service id ({{spotify}} {{appleMusic}} / {{apple}} {{youtube}} {{website}} {{facebook}} …); a line whose link is empty disappears. The default YouTube template has {{listen}} and {{follow}}; an older template's "Listen on Spotify: https://open.spotify.com/ (add the link to the song)" line becomes the links (or goes without links); the Post panel's YouTube description follows the current pick (relink), even for publish.txt written before. Templates on disk are never changed.
- Tags (11 Nov 2026): brand.json "tags" (hashtags added to every song of the artist; without it the artist's name) and "tagStarters" (the genre / mood suggestions on every song). Each song's ranked list: Prepare → Song Details → Tags (song.json "tags"). The Post panel and publish.txt use the top ones per platform (Instagram / Facebook 5, TikTok 8, Shorts 8, YouTube 3 in the description + the Tags box up to 500 characters). Details: docs/screens.md (Song Details → Tags).
