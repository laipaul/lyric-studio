# Data model and workspace folders

_Part of the project brief (CLAUDE.md links here). Database tables and the workspace folder layout. Moved word for word from CLAUDE.md on 30 Oct 2026; keep it up to date when this area changes._

- Project: id, title, artist, cover_path, audio_path, bpm, duration_ms, downbeat_offset (0-3: bar 1 starts N beats later than detected), folder (workspace-relative song folder "songs/<artist>/<title>"; empty = old layout projects/<id>, until migrated), created_at
- LyricLine: id, project_id, index, text, start_ms, end_ms, is_hook, words_json (optional word timings)
- Beat: project_id, time_ms, strength, is_downbeat (as detected; Project.downbeat_offset is applied when read)
- Section: id, project_id, name, start_ms, end_ms, energy (low | medium | high: low halves the cut rate, high doubles it)
- Collection: id, name
- Clip: id, collection_id, path, duration_ms, width, height, thumb_path, source (upload | stock | ai)
- StylePreset: id, name, font, weight, text_case, effect, animation, default_size
- Variation: id, project_id, section_id, seed, cut_rate, style_id, text_size, colour, cinematic_bars, overrides_json
- RenderJob: id, variation_id, status (queued | rendering | done | failed | interrupted), progress, output_path, error, started_at, finished_at, pid (the owning process; queued/rendering jobs whose process is gone become "interrupted", checked by the worker at start and every minute and by the studio)
- VideoMark: id, project_id, video (workspace-relative manifest path, unique), favourite, status (generated | approved | discarded), updated_at
- MakeRun: id, project_id, status (queued | running | done | failed | stopped | interrupted), label, options_json, progress, current, states_json, message, export_dir, pid, stop_requested, created_at, started_at, finished_at, cleared_at (Tasks "Clear finished": hides the entry only) (studio runs; a running run whose worker is gone becomes interrupted; an interrupted/failed job counts only until a later job of the same run, platform and seed is done)

Workspace folder layout (Step 6.2c): one folder per song `workspace/songs/<artist>/<title>/` with the song (WAV/MP3), the lyrics (.txt), `cover.jpg|png`, `hints.lrc` (optional), the vocal stem (optional WAV: analysis only, the main guide for lyric timing) and the backing vocals (optional WAV, never used for timing). Since 31 Oct 2026 the song, lyrics, vocal stem and backing vocals keep the user's own file names ("These Empty Roads (Master).wav", "TER lyrics v3.txt", "These Empty Roads (Lead Vocal).wav"); which file has which role is in `.studio/files.json` (`{version: 1, song, lyrics, vocals, backingVocals, notUsed: [...]}`, names in the folder only; src/node/file-links.ts), read by `songPaths()`, `pnpm make "<song folder>"` (songFolderFiles), pnpm lyrics:compare-voice and the audio service's `--stem auto`. Without a link the old fixed names are the fallback (`song.wav|mp3`, `lyrics.txt`, `vocals.wav`, `backing-vocals.wav`), so songs made before work unchanged and nothing is ever renamed. Files put into the folder by hand are recognised (src/node/song-files.ts, on the Assets tab, before a lyric timing and in pnpm make): an audio file with the song's content is the song (found again after a rename in Explorer; a copy is marked not used), the only .txt is the lyrics when there are none, a name with "Vocal / Vox / Acapella" is the vocal stem and "Backing / Harmonies / BGV" the backing vocals (when there are none yet), another WAV is the vocal stem when it lines up on the song (the L1a check); the rest is asked once on the Assets tab ("What is this file?": lyrics / vocal stem / backing vocals / not used). `.studio/hand-times.json` records the voice the hand-set starts were made on (see docs/lyrics.md). `clips/` (the song's own clips; `clips/_removed/` = removed, never deleted), `clips.json` (optional: the storyboard's story order and clip edits), `exports/<YYYY-MM-DD_HHmm>/<platform>/`, `song.json` (the recipe) and hidden `.studio/` (tool files: `lyrics/` alignments + stored hints + lyrics copies, `settings.json`, `replaced/`, `project-files/`); shared collections `workspace/collections/<name>/`; `workspace/thumbs/`, `workspace/cache/`, `workspace/studio.db`; `workspace/.studio/moved-paths.json` (every folder move, so old manifests still resolve); `workspace/migrations/<date>/` (migration backups + journals). Folder names are readable and Windows-safe (accents kept, `<>:"/\|?*` -> `_`, max 60 chars, " (2)" when taken); renaming title/artist renames the folder (not while another process renders it) and every database path follows. Every song path goes through `songPaths()` (packages/video/src/node/song-folder.ts), which also serves songs still in the old layout (`workspace/projects/<id>/{audio,lyrics,exports,settings.json}`, collections in `workspace/clips/<name>/`) until `pnpm songs:migrate --apply`.

Themes (31 Oct 2026; packages/video src/node/themes.ts): `workspace/themes/<name>/` holds one theme, self-contained so it can be zipped and shared later: `theme.json` (version 1, name, description, author, licence, fonts [{family, files, licence}], look {verseFont, verseWeight, verseItalic, hookFont, hookWeight, hookItalic, verseEffect, hookEffect, accentColour, breathe, heldGlow, chorusLift, shine, textColour, grade (natural | warm | cool | faded | mono | moody), vignette (off | soft | strong), textBacking (none | shadow | glow | band | box), fallback (gradient | colour | cover), fallbackColour, gradeCanvas (on | off), emphasis (off | on), titleStyle (plain | outline | layered | extrude | label), titleWarp (none | arc | wave); src/picture.ts draws them, never changing a clip file}, perPlatform {<platform>: part of look}, createdAt), `fonts/`, `overlays/` and an optional `preview.png`. A folder starting with `_` is skipped (`_removed`). song.json `"theme": "<name>"` names the song's theme; brand.json `"theme"` names the artist's default theme (a new song starts on it). The look fields are never in song.json any more: the recipe order is library → artist → artist:platform → theme → theme:platform → song → song:platform → run. Migration is lazy (ensureSongTheme, the first time a song's recipe is read): a song without look fields moves to the artist's default theme (made from brand.json and named after the artist); a song with its own look gets a theme named after its title (or an existing theme with the same look), and its look fields, their per-platform values and locks leave song.json. pnpm make `--theme <name>` uses another theme for one run.

Deleted songs (31 Oct 2026; library.ts removeSong / restoreSong / removedSongs, song-folder.ts isRemovedSong): "Delete song" moves the song's whole folder to `workspace/songs/_removed/<artist> - <title> (removed YYYY-MM-DD HHMMSS)/` and relocates every stored path (relocatePaths); the project row, its runs and marks stay, so Restore (back to songs/<artist>/<title>, " (2)" when taken) brings everything back. A project whose folder is under songs/_removed is skipped by the Library, Themes (users, ensureAllThemes), Collections (songs using one) and Releases.

### Hook card and End card (31 Oct 2026)
Theme fields hookCard / endCard (off | on, default off), hookCardStyle (default plain) / endCardStyle
(default label; plain | outline | layered | extrude | label). Song fields hookText (empty: the first chorus
line) and endText (default "Stream {title} on Spotify"; {title}, {artist}). Planned on Reels / TikTok /
Shorts as TextCardProps type "hook" / "end" (off: true while the theme has them off); manifest
settings.extra_cards [{type, text, start_s, style}] for the ones drawn.
