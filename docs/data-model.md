# Data model and workspace folders

_Part of the project brief (CLAUDE.md links here). Database tables and the workspace folder layout. Moved word for word from CLAUDE.md on 30 Oct 2026; keep it up to date when this area changes._

- Project: id, title, artist, cover_path, audio_path, bpm, duration_ms, downbeat_offset (0-3: bar 1 starts N beats later than detected), folder (workspace-relative song folder "songs/<artist>/<title>"; empty = old layout projects/<id>, until migrated), created_at
- LyricLine: id, project_id, index, text, start_ms, end_ms, is_hook, words_json (optional word timings)
- Beat: project_id, time_ms, strength, is_downbeat (as detected; Project.downbeat_offset is applied when read)
- Section: id, project_id, name, start_ms, end_ms, energy (low | medium | high: low halves the cut rate, high doubles it)
- Collection: id, name
- Clip: id, collection_id, path, duration_ms, width, height, thumb_path, source (upload | stock | ai)
- StylePreset: id, name, font, weight, text_case, effect, animation, default_size
- Variation: id, project_id, section_id, seed, cut_rate, style_id, text_size, colour, cinematic_bars, overrides_json
- RenderJob: id, variation_id, status (queued | rendering | done | failed | interrupted), progress, output_path, error, started_at, finished_at, pid (the owning process; queued/rendering jobs whose process is gone become "interrupted", checked by the worker at start and every minute and by the studio)
- VideoMark: id, project_id, video (workspace-relative manifest path, unique), favourite, status (generated | approved | discarded), updated_at
- MakeRun: id, project_id, status (queued | running | done | failed | stopped | interrupted), label, options_json, progress, current, states_json, message, export_dir, pid, stop_requested, created_at, started_at, finished_at, cleared_at (Tasks "Clear finished": hides the entry only) (studio runs; a running run whose worker is gone becomes interrupted; an interrupted/failed job counts only until a later job of the same run, platform and seed is done)

Workspace folder layout (Step 6.2c): one folder per song `workspace/songs/<artist>/<title>/` with the song (WAV/MP3), the lyrics (.txt), `cover.jpg|png`, `hints.lrc` (optional), the vocal stem (optional WAV: analysis only, the main guide for lyric timing) and the backing vocals (optional WAV, never used for timing). Since 31 Oct 2026 the song, lyrics, vocal stem and backing vocals keep the user's own file names ("These Empty Roads (Master).wav", "TER lyrics v3.txt", "These Empty Roads (Lead Vocal).wav"); which file has which role is in `.studio/files.json` (`{version: 1, song, lyrics, vocals, backingVocals, notUsed: [...]}`, names in the folder only; src/node/file-links.ts), read by `songPaths()`, `pnpm make "<song folder>"` (songFolderFiles), pnpm lyrics:compare-voice and the audio service's `--stem auto`. Without a link the old fixed names are the fallback (`song.wav|mp3`, `lyrics.txt`, `vocals.wav`, `backing-vocals.wav`), so songs made before work unchanged and nothing is ever renamed. Files put into the folder by hand are recognised (src/node/song-files.ts, on the Assets tab, before a lyric timing and in pnpm make): an audio file with the song's content is the song (found again after a rename in Explorer; a copy is marked not used), the only .txt is the lyrics when there are none, a name with "Vocal / Vox / Acapella" is the vocal stem and "Backing / Harmonies / BGV" the backing vocals (when there are none yet), another WAV is the vocal stem when it lines up on the song (the L1a check); the rest is asked once on the Assets tab ("What is this file?": lyrics / vocal stem / backing vocals / not used). `.studio/hand-times.json` records the voice the hand-set starts were made on (see docs/lyrics.md). `clips/` (the song's own clips; `clips/_removed/` = removed, never deleted), `clips.json` (optional: the storyboard's story order and clip edits), `shotlist.json` (C2, 18 Nov 2026: the planned slots imported from the user's shot list: { imported_at, source, slots: [{ id, order, shows, characters, scene, shot, line, outfit?, tag?, animate? }] }; each slot is "slot:<id>" in clips.json "order"; src/node/shotlist.ts), `storyboards/<platform>-<n>.json` (9 Nov 2026, Theme v2 step 2d: the plan of each video as Shape shows it, written when Shape plans it with the song's own clips or by `pnpm storyboards`; schemaVersion 1, song milliseconds, shot ids sh-NN, text ids line-N / card-<id>, a `locked` list per item (imported: moved cuts, slips, anchors), `edits.unmatched` for edits no shot matches; src/storyboard-file.ts, node/storyboard-file.ts; nothing reads them before step 2e-1), `exports/<YYYY-MM-DD_HHmm>/<platform>/`, `song.json` (the recipe) and hidden `.studio/` (tool files: `lyrics/` alignments + stored hints + lyrics copies, `settings.json`, `replaced/`, `project-files/`); shared collections `workspace/collections/<name>/`; `workspace/thumbs/`, `workspace/cache/`, `workspace/studio.db`; `workspace/.studio/moved-paths.json` (every folder move, so old manifests still resolve); `workspace/migrations/<date>/` (migration backups + journals). Folder names are readable and Windows-safe (accents kept, `<>:"/\|?*` -> `_`, max 60 chars, " (2)" when taken); renaming title/artist renames the folder (not while another process renders it) and every database path follows. Every song path goes through `songPaths()` (packages/video/src/node/song-folder.ts), which also serves songs still in the old layout (`workspace/projects/<id>/{audio,lyrics,exports,settings.json}`, collections in `workspace/clips/<name>/`) until `pnpm songs:migrate --apply`.
- **Version names** (`<song folder>\.studio\versions.json`, 11 Nov 2026; node/versions.ts): `{ "<platform>": { "<run folder>/<platform>/<file stem>": <number> } }`, e.g. `{ "reels": { "2026-11-11_1505/reels/v1": 1, "2026-11-11_1541/reels/v1": 2 } }` (the platform folder is "standard" for a run's top folder). A video gets the next number of its platform the first time it is read (existing ones in creation order: manifest created_at, then run folder, then file stem); entries are never removed or reused, so a discarded or deleted video keeps its number. Tries (Compare looks) have no entry. Written atomically (tmp + rename); a folder that cannot be written still gives the same numbers on every read. Marks (video_mark) stay keyed by the manifest path, never by the name.
- **Clip story notes** (`<song folder>\.studio\clip-notes.json`, 9 Nov 2026; node/clip-notes.ts): `{ about, notes: { <clip content sha256>: { text, clip, updatedAt } } }`, written in Prepare → Clips. Keyed by the clip's content, so a note follows a reordered, renamed, omitted, removed and restored clip and every regeneration (not in clips.json, not in a storyboard); a clip replaced under the same name finds its note by the name. Empty text deletes the note. For the user only: only assets.ts reads it (to show it on the cards); the planner, Make, storyboards, Shape and the assessment never do (test/clip-notes.test.ts).
- **Clip roles and `lineOnly`** (22 Nov 2026; node/clip-roles.ts, clip-edits.ts): every file in `clips\` has a role. **story**: a story moment (dropped, picked from a collection, or sent from Creation with "Send to Storyboard"). **singing**: an anchor in song.json with `sync`, or the `sent` clip of any lipsync take in pictures.json; it plays only on its Lyrics Sync lines. **lineOnly**: clips.json `clips["<file>"].lineOnly: true`, a Creation take that Lyrics Sync copied into `clips\` only so a line (anchor) or a hidden-moment cover can use it. Only story clips show in Prepare → Storyboard (numbered, draggable) and in Shape's clip strip; singing and lineOnly clips keep their entries in clips.json (order, edits), which saving the Storyboard order never drops. The planner (compose.ts `anchorOnly`) never uses a singing or lineOnly clip as gap fill; a lineOnly clip on no line is simply not used. `sendToStoryboard(file, n, { forLine })` (pictures API `send`, `forLine: true` from Lyrics Sync): forLine copies the take, sets `lineOnly` and does NOT add it to `order`; a normal Send from Creation of a lineOnly clip clears the flag and puts it at the END of `order` (nothing else moves; the card says it is now in the Storyboard). A sent clip that is no longer in `clips\` (removed) counts as not sent: Send puts it back from `clips\_removed\` (same file, no duplicate) or copies it again.
- **Shot plans** (`<song folder>\storyboards\`, Theme v2 2d / 2e-1; on screen "shot plan"): `<platform>-<n>.json` per video (src/storyboard-file.ts; since 2e-1 each shot also holds `render`, the exact detail the renderer draws: where playback starts in the clip, its length there, a photo's move, dissolve, loop blend; `output.audio` the fades; `inputs.media` the clip files (name, sha256) and `inputs.planKey`, a fingerprint of everything the plan is made from: the song, its lyric timing, the clips and clips.json, the song's settings for that platform, the variation). `<id>.previous.json`: the plan before the last one that was replaced (one step back). `<platform>-<n>~<kind>-<name>.json`: a Try other looks video (kind theme / fonts / pictures; `output.try` = { kind, label, theme | pairing | clipSet }), never the video's own. Make settles each video's plan before making it (node/storyboard-file.ts settleShotPlan: new / same / replanned (saved again, the old one kept as .previous) / kept (same fingerprint but the app would plan it differently now: the saved plan is made)) and compiles the props from it (compileShotPlan: shots, cuts, part of the song, fades and lyric timing from the file; the look from the song now); a run keeps a copy next to each video (`<name>.shotplan.json`) and the manifest says which plan and what happened (`shot_plan`: id, file, copy, status, note). A plan saved again, or kept as saved, is named in the run's message in Tasks.

Characters and scene cards (C1, 18 Nov 2026; packages/video src/node/characters/*):
- **Folders:** `workspace/characters/<name>/` and `workspace/scenes/<name>/` (Windows-safe names). A removed card
  (Remove card, 26 Nov 2026) moves to `characters/_removed/<name> <time>/` (or scenes); its card.json `removed`
  {id, at, scope_kind, scope_value, folder} brings it back with Restore (same id); its database row goes meanwhile. Each holds:
  - `card.json`: version 1, kind, name, created_at, reference (the picture sent to the models: the upload, or
    `reference_cropped.jpg` after Crop to face), original, reference2?, check? / check2? (the reference or location
    check), and versions [{n, status draft | locked, created_at, locked_at?, model, outfit?, props?, description?}];
    the Wardrobe (21 Nov 2026): main_look? (the pack's own outfit's name, default "Main look") and looks? [{id, name,
    outfit?, outfit_split?, model, closeup (also a close-up in the look), status draft | locked, created_at, locked_at?}].
  - the picture(s); `_replaced/<time>/` the card's earlier pictures (Replace picture, 26 Nov 2026; card.json
    `replaced` [{at, folder, reference, original, check?}], Restore swaps them back);
  - `calibration.json` (characters: the face-check lines on a song's clips);
  - one folder per version, `v1/`, `v2/` …, holding:
    - each try `<id>_t<k>.png` (body views also `<id>_t<k>_full.png`, the model's own picture before the app's
      neck crop);
    - the chosen one copied to `<id>.png` (ids closeup, three_quarter, body_front, body_back; the extra views made only
      when asked: closeup_teeth, profile, body_full (not cropped at the neck); scenes wide_left, wide_right, detail);
    - `report.json` (model, endpoint, thresholds, items with every try's request ID, URL, score, light and text,
      request_ids, spent_usd);
    - `sheet.jpg` (the contact sheet, with scores); `character_sheet.png` (the Character sheet: the views side by side,
      no captions; made again when a view is newer; 25 Nov 2026);
    - `_aside/` (26 Nov 2026, cleanup.ts): pictures taken off the card with ✕, as `<id> <time>.png` (+ ` full.png`),
      listed in `_aside/aside.json` [{file, id, label, at, full?, chosen, light, text}] for Restore;
    - your own pictures (Add my pack / Use my own picture): tries with `own` (the file name), also kept as given in
      `<id>_t<k>_own.png` (for Move to);
  - `looks/<look id>/` (characters, the Wardrobe): the look's tries and chosen `body_front.png`, `body_back.png`
    (+ `closeup.png` when asked) and its `report.json` (no contact sheet). The main look is the version's own views.
- **A song's card versions** (26 Nov 2026): `production/production.json` `versions` {card id: version n} = the locked
  version a song is kept on (Keep on v1 after v2 was locked; node/card-versions.ts); missing = the newest locked version.
  card.json `cover`: the card's thumbnail until a version is locked (a picture in the card folder).
- **A song's looks:** `production/production.json` `looks` {card id: look id} = which look each cast character wears
  (missing or "main" = the main look); the Song brief uses that look's outfit.
- **Versions:** a locked version is read-only. New version copies the latest folder into the next one as a draft.
  Nothing is deleted. The version in use is the latest locked one (`usableVersion`): while a newer draft exists the
  card row keeps status locked and the locked version's number.
- **Table `card`:** id, kind, name (unique per kind), folder, scope_kind artist | ep | song, scope_value, status
  draft | locked (locked once any version is), version (the version in use; the newest while nothing is locked),
  created_at, updated_at.
- **Table `card_job`:** id, card_id, kind pack | view | fetch | calibrate, status (as make_run), label,
  options_json, progress, current, message, cost_usd (the estimate of what was sent), pid, created_at, started_at,
  finished_at, cleared_at. The jobs run in the studio's own process; a job whose process is gone is marked
  interrupted. Migration 0007_cards.

Film looks (22 Nov 2026; packages/video src/node/film-looks.ts, film-look-writer.ts): `workspace/film-looks/<name>/` holds one Film look: `look.json` (version 1, name, line = the words added to every Animate and singing prompt of the songs that use it, midjourney = the same look as Midjourney words, still = the reference still's file name, feel = "natural" (default) | "dreamy": which realism rules every take is sent with, realism.ts, 25 Nov 2026, createdAt) and `still.jpg|png|webp` (a replaced still goes to the folder's `.replaced/`). A folder starting with `_` is skipped (`_removed`: deleted ones, with Restore). song.json `"filmLook": "<name>"` names the song's look (Prepare → Creation). Each take in pictures.json records `quality` ("draft" = Seedance 2.5 Flash 480p, 25 Nov 2026; "standard"; "best"; "magi2" = MAGI-2 1080p on WaveSpeed, 27 Nov 2026), `mvShot` (a shot of a music video made elsewhere, its number), `finalOf` / `final` (Make final, final.ts: an upscaled final and its draft), `filmLook` (the name), `look` (the line as sent) and `feel` (the realism rules as sent; absent on takes made before 25 Nov 2026, which keep the old prompt), `feeling` / `feelingTo` (Feeling per section, feelings.ts, 25 Nov 2026: the feeling as sent, and the one a singing take turns to when its lines run into a section that feels different); a picture's own `feeling` (pictures.json) wins over its shot's section; song.json "sections" entries carry an optional `feeling` (one of tender, longing, hope, joy, pride, defiance, grief, calm, or the user's own word, at most 30 characters); a later change of the look never changes a take. filmLookFor(ws, projectId) decides a take's look and feelFor(ws, projectId) its feel (natural for a song without a look) (Scenes will add their own there).

Themes (31 Oct 2026; packages/video src/node/themes.ts): `workspace/themes/<name>/` holds one theme, self-contained so it can be zipped and shared later: `theme.json` (version 1, name, description, author, licence, fonts [{family, files, licence}], look {verseFont, verseWeight, verseItalic, hookFont, hookWeight, hookItalic, verseEffect, hookEffect, accentColour, breathe, heldGlow, chorusLift, shine, textColour, grade (natural | warm | cool | faded | mono | moody), vignette (off | soft | strong), textBacking (none | shadow | glow | band | box), fallback (gradient | colour | cover), fallbackColour, gradeCanvas (on | off), emphasis (off | on), titleStyle (plain | outline | layered | extrude | label), titleWarp (none | arc | wave), textLayout (centre | lower | bighook, 1 Nov 2026: src/text-layout.ts; lower = the lyric area's centre at LOWER_THIRD_AT 0.68 of the usable area, bighook = chorus lines x BIG_HOOK_SCALE 1.3 via lyricEffects.hookScale; props textLayout / lyricsAt record it; never with YouTube's cover / stills), lineShape (subtitle | stacked), lineBuild (replace | build), finalHook (off | on) (9 Nov 2026, Theme v2 step 2b part 2: src/line-shape.ts, docs/theme-rules.md LIN-01..06; props lyricEffects.lineShape / lineBuild, the final hook as LyricLineProps.scale); src/picture.ts draws them, never changing a clip file}, moods (Romantic | Night | Warm | Minimal | Bright | Moody: the Themes page's mood filters), perPlatform {<platform>: part of look}, createdAt), `fonts/`, `overlays/`, an optional `preview.png` and an optional **Theme cover** `cover.jpg|png|webp`, or a video `cover-video.mp4|mov|m4v|webm` with its first frame as `cover.jpg` (FFmpeg) (1 Nov 2026: the picture its previews show on the Themes page; set / changed / removed there, the old one kept in the theme folder's `_replaced/`; a duplicate keeps it; without one the previews show a neutral backdrop in the theme's colours, never a song's picture). A folder starting with `_` is skipped (`_removed`). song.json `"theme": "<name>"` names the song's theme; brand.json `"theme"` names the artist's default theme (a new song starts on it). The look fields are never in song.json any more: the recipe order is library → artist → artist:platform → theme → theme:platform → song → song:platform → run. Migration is lazy (ensureSongTheme, the first time a song's recipe is read): a song without look fields moves to the artist's default theme (made from brand.json and named after the artist); a song with its own look gets a theme called "<title> look" (since 1 Nov 2026, description "Made from <title>'s look on <date>"; older ones named exactly like the song, description "The look <title> had", are renamed once by plainSongThemeNames, songs and brand.json following) (or an existing theme with the same look), and its look fields, their per-platform values and locks leave song.json. pnpm make `--theme <name>` uses another theme for one run.

Deleted songs (31 Oct 2026; library.ts removeSong / restoreSong / removedSongs, song-folder.ts isRemovedSong): "Delete song" moves the song's whole folder to `workspace/songs/_removed/<artist> - <title> (removed YYYY-MM-DD HHMMSS)/` and relocates every stored path (relocatePaths); the project row, its runs and marks stay, so Restore (back to songs/<artist>/<title>, " (2)" when taken) brings everything back. A project whose folder is under songs/_removed is skipped by the Library, Themes (users, ensureAllThemes), Collections (songs using one) and Releases.

### Hook card and End card (31 Oct 2026)
Theme fields hookCard / endCard (off | on, default off), hookCardStyle (default plain) / endCardStyle
(default label; plain | outline | layered | extrude | label). Song fields hookText (empty: the first chorus
line) and endText (default "Stream {title} on Spotify"; {title}, {artist}). Planned on Reels / TikTok /
Shorts as TextCardProps type "hook" / "end" (off: true while the theme has them off); manifest
settings.extra_cards [{type, text, start_s, style}] for the ones drawn.

- **Production (G1, 21 Nov 2026):** `<song folder>\production\production.json` ({ "cast": [card ids from the card table], "bible": "song" | "ep" }) and `production\bible.md` (the song's own story bible); an EP's shared bible is `workspace\eps\<EP>\bible.md` (its earlier text in `eps\<EP>\.studio\replaced\`). A song's replaced bible.md is in its Replaced files (role "bible", Restore).
- **Creation (G2, G2b, 21 Nov 2026; first called Pictures):** `<song folder>\pictures\` holds Paul's pictures and videos from anywhere (own names), `takes\` the takes made there ("<picture> take N.mp4"), and `pictures.json` ({ "pictures": { "<file>": { "source" (label: "Added by you", "Midjourney", "From <site>"), "mood", "sent" (the clip it was sent to the Storyboard as), "upload": { service, url, at } (the picture's public URL, reused 5 days), "takes": [ { n, service, quality, model, status, started_at, ended_at, request_id, poll_url, cost_usd (estimate), file, sent, error, pid } ] } } }; "clip" on a take from the first build reads as "sent"). Nothing goes to `clips\` until Send to Storyboard, which copies it there at the end of clips.json "order". `workspace\creation.json`: Paul's defaults for every song (service, quality, takes, cap). Keys: WAVESPEED_API_KEY, HIGGSFIELD_API_KEY ("id:secret") in .env; LYRIC_GENERATE_STUB=1 (tests) makes takes locally with FFmpeg and sends nothing.
- **Singing lines (G3, 21 Nov 2026):** `<song folder>\pictures\singer.json` { "lines": { "<line>": "<Creation file>" } }. A singing clip is a take of its picture or video in pictures.json with "kind": "lipsync", "line", "sync_ms" / "to_ms" (the song time of the vocal piece: from 0.5 s before the downbeat before the line to two bars after it is sung), model "InfiniteTalk"; its file `pictures\takes\<picture> sings line N.mp4` (sound removed), copied to `clips\` at the end of the order and anchored in song.json { line, clip, sync } (seconds). Since 21 Nov 2026 (takes): singer.json "resolution": "480p" | "720p" (default 720p; what the next take is made at); each lipsync take records "resolution" and, when it arrived while another take of the same group (same picture, same "line" and "through") was in use, "fresh": true ("New — compare"; such a take is copied to `clips\` only when chosen). "In use" is not stored: it is the take whose clip ("sent") is the song.json singing anchor on its lines. A lipsync take of a piece longer than 10 s has "parts" [{ fromMs, toMs, request_id }] (about 8 s each, on downbeats): made one after another from the last frame of the one before, joined into its one file. A picture's "removedTakes" (Clean up / ✕, 21 Nov 2026): takes put aside with "removed_at", their files in `pictures\takes\_removed\`; Restore moves them back to "takes"; nothing is deleted. Since 28 Nov 2026 also "engine" (the song's last choice: "infinitetalk" | "mv"), "engines" / "scenes" (per group's first line), "aspect" ("9:16" | "16:9", the MV Generator's shape) and "resolution" may be "1080p" (MV Generator only). An MV Generator take: kind lipsync, model "MV Generator", engine "mv", handles {inMs, outMs} (the voice sent before / after its range, cut off again), aspect, scene, warnings? (plain words: length off, a cut at m:ss.s).
- **Favourites (♥, 25 Nov 2026):** pictures.json `"fav": true` on a picture and/or on a take (absent = not a favourite). Only a mark to spot Paul's favourites (Creation ♡ on each picture and finished take, Compare ♡ on each tile, "Favourites only" switches); it changes nothing else, and Clean up never puts a favourite take aside. API: pictures POST { action: "fav", file, n (null: the picture), on }.
- **Shots filled in Creation** (C3 Part 1, 22 Nov 2026): pictures.json "slot" on a picture = the shot list item it belongs to; shotlist.json "filled" { <slot id>: <clip> } = the clip that fills it ("Use for shot"). A filled slot is no longer "slot:<id>" in clips.json order (its clip is there); a re-import keeps "filled" for ids still in the list; Remove all planned slots removes the empty slots only. (25 Nov 2026) A file dropped on a shot whose bytes are already in Creation is not skipped: that existing file is linked to the shot (addPictures returns `existing`, placeDropped links it). A picture, or one of its takes, whose "sent" equals the clip filling a shot (filled or filledWide, case-insensitive) and that has no slot of its own sits on that shot, computed on read (effectiveSlot in animate.ts, used by picturesView and productionView; pictures.json is not written); a picture with its own other slot stays there.

Music video made elsewhere (27 Nov 2026; src/music-video.ts, node/music-video.ts): pictures.json `pictures["<video>"].mv` = { at, matched, score (0-1, the same recording ≈ 0.99), offsetMs (song time of the video's first frame), driftMs, durationMs, width, height, usd (WaveSpeed Music Video Generator price estimate: $0.03/s at 480p, $0.06/s at 720p), shots: [{ fromMs, toMs }] (video time) }. Each shot used is a take of the video (takes/<video> shot N.mp4, no sound, `mvShot`, model "WaveSpeed Music Video Generator", cost 0: the cost is on mv; `quality: "draft"`, so Make final upscales it to 1080p, the final keeping `mvShot`); a shot with sung lines is a `kind: "lipsync"` take (line, through, sync_ms, to_ms) placed with a song.json anchor with `sync`, like any singing take; one without lines is sent to the Storyboard. A take's `handPicked: true` marks a music-video shot Paul put on its lines himself (Use on its lines, or "Use this one" in Best shot for each line): "Use the best for every line" never replaces it. Takes QA `qa.sim` (27 Nov 2026) is the face's median likeness to the picture (SFace cosine); for a music-video shot the reference is the first picture the video was made from in the app (else the video's first frame). Make a music video (27 Nov 2026): a take of the first picture with `kind: "musicvideo"`, `section` { fromMs, toMs } (the stretch of the song sent), `refFiles` (the pictures), `aspect`, `resolution`, `prompt`, `cost_usd`, `request_id`, and `made` = the video it became (its own item in pictures\, with `mv`).
